## 결과

- 페이지 하나의 광고 적용 공수: 평균 **3일 → 1시간 이내** (기획·QA·배포를 뺀 순수 개발 공수)
- 신규 광고 지면 **7개** (v1 배포 2025.10부터 퇴사 2026.08까지)
- NAM fallback 적용으로 **월 690만 원** 신규 광고 수익 (2026년 5월 기준)
- 매일포인트 받기 개편 후 핵심 콘텐츠 CTR **+12%** (2026.05–07, 개편 전 같은 기간 대비)

수치는 사내 광고 운영 지표 기준입니다.

## 배경

KB스타뱅킹은 네이티브 앱이 자체 시스템 '스타루트'를 거쳐 WebView 화면을 띄우는 구조입니다. 새 광고 지면이 생길 때마다 개발자가 광고 연동을 따로 구현했고, 페이지 하나에 순수 개발 공수만 평균 3일이 들었습니다. 페이지마다 광고 타입이 다르고 개발자마다 구현 방식도 달라서 유지보수가 어려웠습니다. 광고가 비었을 때 다음 공급자로 넘기는 공통 기준도 없었습니다.

## 설계

- 광고 요청, 응답 정리, 유형별 렌더링(banner·icon·swiper·button·card), 노출 집계를 `useAd` 하나로 합쳤습니다. 노출은 광고가 실제로 화면에 보일 때만 셉니다(IntersectionObserver).
- 광고가 비거나 요청이 실패하면 DMP → 하우스배너 → 외부 광고(NAM) 순으로 자동으로 넘어갑니다. 순서와 전환 기준은 런타임 안에서만 정합니다.
- 하우스배너의 노출 기간, 확률, 하루 노출 제한은 별도 모듈로 뺐습니다. 정책이 바뀌어도 페이지 코드는 고치지 않습니다.
- 외부 SDK의 로딩과 초기화는 런타임이 관리합니다. 컨테이너별 인스턴스는 WeakMap으로 들고 있고, 렌더 완료는 MutationObserver로 확인합니다.
- 새 소재가 다 뜨기 전까지는 기존 광고와 영역 높이를 그대로 둡니다. 광고 공급자 한 곳이 실패해도 화면 전체 레이아웃은 깨지지 않습니다.

광고 하나가 나가기까지의 순서입니다.

```
페이지          useAd(지면 id) 호출
  1. DMP        사내 광고 서버. 응답을 하나의 형식으로 정리
                ↓ 비었거나 실패하면
  2. 하우스배너  기간·확률·하루 노출 제한을 통과한 1건
                ↓ 없거나 이미지가 실패하면
  3. NAM        Buzzvil SDK 초기화를 확인한 뒤 렌더
                ↓ 렌더 완료
노출 기록        화면에 보일 때만 Impression
```

## 운영하며 고친 문제 3개

셋 다 개발자 도구로는 상태가 보이지 않는 타이밍 문제였습니다. 로컬에서 발생 조건을 재현하고, 같은 동작을 반복해서 원인을 찾았습니다.

### 1. 새로고침해도 광고가 바뀌지 않음

- **진단**: 광고 응답 조건을 바꿔 가며 같은 동작을 수십 번 반복해 재현했습니다. 광고 인스턴스 상태가 개발자 도구에 보이지 않아서, 요청 → 렌더 → 갱신 순서도를 그려 어긋나는 지점을 찾았습니다.
- **원인**: 새로고침할 때 이전 NAM 인스턴스가 컨테이너에 남아, 새 요청이 와도 이전 소재를 그대로 내보내고 있었습니다.
- **해결**: 동작을 둘로 나눴습니다. 새로고침(`refreshNam`)은 이전 인스턴스를 지우고 다시 그리고, 화면 재방문(`preserveNam`)은 기존 광고를 그대로 둡니다.
- **결과**: WebView 재진입, Pull to Refresh, 소재 갱신에서 모두 의도한 광고가 나갑니다.

### 2. 하우스배너로 바뀌는 순간 화면이 흔들림

- **진단**: DMP 조회 뒤 하우스배너 소재가 있을 때만 광고를 교체하는데, 바뀌는 찰나에만 화면이 덜컹거렸습니다. 교체 시점의 실행 순서를 흐름도로 그려 단계별로 따라갔습니다.
- **원인**: 새 배너 이미지가 뜨기 전에 기존 광고와 컨테이너 높이를 먼저 비워서 레이아웃 시프트가 생겼습니다.
- **해결**: 이미지를 미리 불러와 성공했을 때만 교체하고, 시간 초과나 실패 때는 기존 광고를 유지합니다. 렌더가 끝날 때까지 광고 영역 높이도 고정합니다.
- **결과**: 하우스배너 로드가 실패해도 기존 광고와 레이아웃이 그대로 유지됩니다.

### 3. Pull to Refresh를 연타하면 광고 영역이 빔

- **진단**: 새로고침하면 DMP → 하우스배너 → NAM 파이프라인 전체가 처음부터 다시 돕니다. 연속 새로고침을 반복해 보니, 이전 실행이 끝나기 전에 새 요청이 들어와 두 흐름이 겹쳤습니다.
- **원인**: 뒤에 온 요청이 진행 중인 앞 요청의 상태를 덮어써 렌더가 멈추고, 광고 영역이 비었습니다.
- **해결**: 앞 요청이 끝날 때까지 뒤 요청을 막는 잠금을 렌더링 파이프라인에 넣었습니다.
- **결과**: 새로고침을 연타해도 광고가 순서대로 정상 노출됩니다.

## 매일포인트 받기 개편 · 캠페인 어드민

버즈빌과 함께 운영하는 리워드 화면을 개편했습니다.

- 외부 브라우저로 나갔다 돌아오던 동선을 인앱브라우저로 바꿨습니다.
- 사내 디자인 시스템에 맞춰 화면을 다시 정리하고, 스켈레톤과 로딩 타이밍을 조정해 첫 진입 대기 시간을 줄였습니다.
- 혜택홈 핵심 콘텐츠 일부를 앱 네이티브 영역에도 노출해 들어오는 경로를 늘렸습니다.
- 캠페인 상태와 노출 조건을 앱 심사·배포 없이 바꿀 수 있는 운영 어드민을 만들었습니다.

개편 후 핵심 콘텐츠 CTR이 **12%** 올랐습니다(2026.05–07, 개편 전 같은 기간 대비).

## 연간 광고 수수료 14억 원 목표

2026년 연간 광고 수수료 목표는 14억 원(인하우스 배너·그룹사 광고 수주)이었고, 조기에 달성했습니다. 제 몫은 광고가 실릴 자리를 넓힌 일입니다. 혜택홈과 테마별 서비스의 지면을 늘렸고, 매일포인트 받기 화면을 개편했고, useAd를 5개 페이지에 추가로 적용했습니다.
